<p>第一层是本地。先确认自己的基础网络是否稳定，路由器是否重启，系统代理设置有没有被改动，浏览器插件是否干扰。这一层最靠近你，排查成本最低，也最常被跳过。从最简单的可能查起，是效率最高的做法。</p>

<p>第二层是中间配置。检查出口设置是否正确、是否有多套配置互相冲突、断线后是否配置了自动恢复。很多频繁掉线其实是配置里同时跑了两套设置，彼此打架。把配置面收敛到一套，问题常常就消失了。</p>

<p>第三层才是资源端。如果前两层都排除掉，才轮到怀疑资源本身。这时候要问供应商要状态记录，看是不是出口在维护、是不是共享出口被别人跑满。资源端的问题你改不了配置，只能换或等，所以放在最后查。</p>

<p>排查要按顺序来，这也是信息增量所在。假设你一掉线就换资源，换完好了也说不清是换对了还是恰好恢复了，下次再掉还是抓瞎。按顺序排除，每一步留记录，才能知道到底是哪一环的问题。</p>

<p>还要区分偶发和频繁。一天掉一次和一小时掉三次，性质完全不同。偶发的可以先观察，记下时间和当时的操作；频繁的才值得投入精力排查。把频率先量化，再决定要不要动手，避免为偶发问题过度折腾。</p>
